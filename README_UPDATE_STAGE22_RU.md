# Stage 22 — исправление авторизации и дизайна фильтра

## Что исправлено

- Header больше не кэшируется как статический блок. После входа пользователь должен оставаться залогиненным при переходе на “Объекты”, “Карта”, “Архив” и другие публичные страницы.
- API избранного и сохранённых поисков принудительно работают в dynamic/no-cache режиме.
- Cookie пользователя читается стабильнее: сначала из request, затем из server cookies.
- Вход/регистрация добавляют no-store заголовок после установки cookie.
- Убраны пустые голубые кружки в многовыборе.
- Многовыбор Bundesland / Тип объекта / Использование стал компактнее и аккуратнее.
- Выпадающие списки теперь вертикальные, без горизонтального скролла.
- Фильтр визуально выровнен: поля, dropdown и ползунки выглядят ровнее.

## Установка

1. Сделать backup:

```powershell
Copy-Item -Recurse D:\Projects\zvg_frontend_mvp D:\Projects\zvg_frontend_mvp_backup_stage22
```

2. Распаковать архив `zvg_stage22_filter_auth_cleanup_update_files.zip`.

3. Скопировать папки/файлы поверх проекта:

```txt
app
components
lib
```

в:

```txt
D:\Projects\zvg_frontend_mvp
```

4. Проверить сборку:

```powershell
cd D:\Projects\zvg_frontend_mvp
npm run build
```

5. Проверить локально:

```powershell
npm run dev
```

6. Выйти и войти заново в аккаунт пользователя.

7. Проверить:

```txt
/login
/cabinet
/
/map
/archive
```

После входа меню должно оставаться в состоянии “Кабинет / Выйти”.

8. Проверить избранное:

```txt
1. Войти пользователем.
2. Перейти на “Объекты”.
3. Добавить объект в избранное.
4. Перейти в кабинет.
5. Объект должен быть в избранном.
```

9. Отправить на GitHub:

```powershell
git add .
git commit -m "Fix user session caching and improve filter UI"
git push
```

## Важно для Vercel

Проверь, что в Vercel задана переменная:

```txt
USER_SESSION_SECRET
```

Если ты поменяешь `USER_SESSION_SECRET`, старые сессии перестанут работать. После деплоя нужно выйти и войти заново.
